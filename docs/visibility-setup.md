# Visibility setup

Apply `drizzle/0011_curved_supernaut.sql` to the same D1 database as StreetVouch before opening the new manager page. Existing review and feedback tables are unchanged.

In the Google Cloud project used for Business Profile, enable the Search Console API, Google Analytics Data API, and Google Analytics Admin API. Add the production `/api/visibility/callback` URL to the existing OAuth client's authorised redirect URIs. Keep `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, and `GOOGLE_TOKEN_ENCRYPTION_KEY` configured. OAuth requests read-only `webmasters.readonly` and `analytics.readonly`; the Business Profile consent remains separate. Google may require OAuth app verification when moving beyond test users or requesting sensitive scopes. Each owner must sign in and consent, then select a verified Search Console property and an accessible GA4 property.

The manager can run a manual refresh. The GitHub Actions workflow `.github/workflows/visibility-collect.yml` calls the protected collection route daily at 05:17 UTC and can be run manually. Set the same randomly generated `VISIBILITY_CRON_SECRET` as a secret in Sites production and the GitHub repository. Deploy a saved Site version after setting the Sites secret. Check that the GitHub Actions run succeeds and that `last_collected_at` updates for a connected business. GitHub's scheduled runs may be delayed. The route processes at most ten connected businesses per call, oldest collection first. Add more calls or batching as account count grows. Set a narrow Google API quota and monitor failures. Search Console data is requested only through three days ago because recent values may be incomplete. Search Analytics query and page rows are capped at 50,000 per collection by the API and this implementation; large properties may have incomplete long-tail detail. Daily property totals are collected separately. A further 90-day query-and-page request stores the most shown page for each query where Google returns a pair. Opportunities use this evidence to draft up to three actions; page matching can be unavailable for rare queries and is not a guarantee of the page a customer saw in a particular search.

The current website check reads the business's configured HTTPS homepage only when its host matches the verified Search Console property. It checks availability, redirects, title, noindex, a basic robots.txt rule, a conventional sitemap location, known LocalBusiness types, and Search Console URL Inspection when the API permits it. It does not yet inspect every service page or fully validate structured data and sitemap contents. Treat a missing structured-data result as a prompt for review: this simple check may miss valid markup. Google Business Profile health currently reuses the existing review connection and shows imported reviews and replies; profile actions and business details are unavailable. Bing AI citation data and sampled AI answers are unavailable. AI referrals are identifiable GA4 session sources only, and may undercount actual AI influence.

The Alerts view documents and lets a manager change the rule. It compares two complete periods of 7, 14 or 28 days, requires a minimum prior volume, and excludes the latest three days. Seasonality is not yet modelled, so alerts describe likely possibilities rather than causes. Search clicks, Analytics organic sessions, Business Profile actions, and bookings must remain separate measures.
